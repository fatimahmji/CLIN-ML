# Read the release step by step

## 1. Start with run_release.py

This short file shows the entire workflow in order: tests -> training -> audits -> verification -> report. It calls other modules so each file has one clear responsibility. `--input` is the original CSV path; `--output` is where generated results go.

## 2. Read data_preparation.py

`read_visits()` loads the table, validates required fields, records raw blank rates and marks invalid acuity values missing. `source_row` preserves provenance. For example, an original VA of 120 becomes missing with `va_invalid=True`; it never becomes 100.

`label_eye()` looks at one patient's one eye. It requires a unique day-zero injection baseline. `select_followup()` chooses the closest valid VA to day 180 within days 150–210. For example, day 179 wins over day 160, even if day 160 has a larger gain. At equal distance, the earlier day wins. Conflicting selected-day measurements are excluded.

Response is `int(followup_va - baseline_va >= 5)`. A gain of exactly five is response=1. An absent follow-up is not response=0; the eye remains in the audit but out of supervised training. `build_eye_level_labels()` applies this policy to every patient-eye group.

## 3. Read test_labels.py

These are invented tiny tables used only to verify rules, never train the real model or claim clinical performance. Thirteen tests cover boundaries, ties, invalid values, missing identifiers, duplicates, conflicts, the response threshold and calibration behavior. You can run them alone with `python -m unittest test_labels.py`.

## 4. Read training.py

`make_preprocessor()` prepares numeric acuity and categorical age. Scaling/imputation/encoding are fitted only within training data or the training fold. `make_models()` defines the original fixed Logistic Regression, Random Forest and Gradient Boosting settings. The main function creates patient-grouped splits and grouped five-fold training CV. Both eyes stay with their patient.

Models are fitted on training patients and selected by validation AUROC, preserving V1's procedure. The chosen model is evaluated on test patients; this test set was inspected previously. `save_evaluation_charts()` draws ROC, precision-recall, calibration and confusion-matrix plots. `save_feature_importance()` shuffles baseline inputs on validation patients to assess predictive reliance, not causality.

The patient-cluster bootstrap resamples patients with all their eyes 1,000 times to summarize test-metric uncertainty. Export and reload must produce matching probabilities. Fixed seeds preserve the reference experiment; nothing here searches for a better-looking test score.

## 5. Read evaluation.py and audits.py

`metrics()` returns AUROC, average precision (AUPRC), sensitivity, specificity, F1, Brier and confusion counts. Threshold-dependent metrics use 0.50. AUROC is ranking ability, not accuracy; lower Brier is better.

`run_audits()` saves cleaned visits and reports raw blanks separately from invalid measurements and post-cleaning missingness. It compares baseline VA, age, sex and ethnicity between included and excluded eyes. The VA standardized mean difference divides the mean difference by the square root of the average of the two sample variances. It describes a difference, not proof or correction of selection bias.

An acuity-only logistic comparator uses the same training/test patients. This asks how much of performance is available from baseline VA alone. It is fixed, not tuned or selected on test results. Calibration summaries report mean prediction versus observed response, Brier, and ECE across ten equal-width probability bins. ECE depends on binning and is not clinical certification.

## 6. Read verify.py

The regenerated labels, partition assignments and reference probabilities are compared with frozen V1 artifacts. Verification also independently checks nearest source follow-up, reload probabilities and invalid inference inputs. A failure stops the release command rather than silently updating the reference. `verification.json` records successful checks.

## 7. Read inference.py

Supply baseline VA and a supported age band. The function validates them, loads the complete saved pipeline and returns a probability. `schema.json` describes exact inputs. This is a research estimate under observed care, not advice to inject, withhold or switch medication. Only load trusted joblib files.

## 8. Read performance_report.md

The report is generated by make_report.py from computed JSON/CSV outputs. It includes the reference results, acuity-only comparison, numerical calibration, attrition and limitations. SOURCE_AND_PROTOCOL.md contains the source definitions verified after the original experiment; this release's documentation replaces those outdated uncertainty statements.

No OCT outcome is implemented: the source CSV lacks thickness measurements. Clinical review and independent validation remain pending even when every software check passes.
